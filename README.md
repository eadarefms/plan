# نظام تتبع خطط العمل - AREF Marrakech-Safi

تطبيق ويب كامل (وليس نموذجًا تجريبيًا) لتتبع تنفيذ خطط العمل السنوية على مستوى الأكاديمية الجهوية للتربية والتكوين لجهة مراكش آسفي، بمديرياتها الإقليمية الثمانية.

كل الأدوات المستعملة في هذا المشروع **مجانية بالكامل** (قاعدة البيانات، الاستضافة، جميع المكتبات) — التفاصيل في قسم "النشر على الويب" أسفله.

---

## 1. البنية التقنية (Stack)

| الطبقة | التقنية | لماذا مجانية |
|---|---|---|
| Frontend | React + TypeScript + Vite + Tailwind CSS + Recharts | مكتبات مفتوحة المصدر بالكامل |
| Backend | Node.js + Express + TypeScript | مفتوح المصدر |
| ORM | Prisma | مفتوح المصدر |
| قاعدة البيانات (محليًا) | **SQLite** (ملف واحد، بدون أي إعداد) | مدمج، لا يحتاج خادم |
| قاعدة البيانات (إنتاج) | **PostgreSQL مجاني** عبر Neon.tech أو Supabase (اختياري) | كلاهما لديه باقة مجانية دائمة |
| المصادقة | JWT + bcrypt | مكتبات مجانية |
| استضافة Backend | **Render.com (Free Web Service)** أو **Railway (Free Trial)** | باقة مجانية |
| استضافة Frontend | **Vercel** أو **Netlify** | باقة مجانية دائمة للمشاريع الشخصية |

لا حاجة لأي بطاقة بنكية أو اشتراك مدفوع لتشغيل المشروع محليًا أو نشره بالكامل مجانًا.

## 4. الصلاحيات (RBAC) — مطبّقة في الـ Backend وليس فقط الواجهة

- **منسق إقليمي (PROVINCIAL)**: مرتبط بمديرية واحدة عبر `directorateId` في جدول `User`. كل طلب API يمر عبر `assertDirectorateAccess()` الذي يرفض أي وصول لمديرية أخرى، بغض النظر عمّا يُرسل من الواجهة.
- **منسق جهوي (REGIONAL)**: وصول كامل لجميع المديريات + لوحة القيادة الجهوية.
- **مدير النظام (ADMIN)**: كل صلاحيات المنسق الجهوي + إدارة المستخدمين + الاطلاع على سجل التغييرات.

راجع `backend/src/middleware/auth.ts` و`backend/src/routes/actions.routes.ts` لتفاصيل التطبيق.

## 5. منطق الحسابات المهمة

- **نسبة الإنجاز** = القيمة المنجزة ÷ القيمة المستهدفة × 100 (معالجة القسمة على صفر في `computeCompletionRate()`، ملف `backend/src/services/actionPlan.service.ts`).
- **حقل "منسق العملية"**: حقل نصي حر (كما في نموذج Excel الأصلي) وليس قائمة مغلقة، مع اقتراحات تلقائية (Autocomplete) من الأسماء المستعملة سابقًا في نفس المديرية.
- **نوع القيم (نسبة مئوية / عدد)**: كل عملية تحمل خاصية `isPercentage` تحدد كيفية عرض القيم الثلاث (الحالية، المستهدفة، المنجزة) — إما كنسبة % أو كعدد مطلق، حسب طبيعة المؤشر.
- **العملية المتأخرة** = تاريخ النهاية المخطط قد مضى + العملية ليست منجزة (`computeEffectiveStatus()`، ملف `backend/src/utils/status.ts`) — محسوبة ديناميكيًا في كل قراءة، فتبقى صحيحة دومًا دون الحاجة لمهمة مجدولة (cron).
- **زر "تم الإنجاز"**: عند التفعيل تتحول الوضعية تلقائيًا إلى "منجزة" ويُسجَّل تاريخ الإنجاز.

## 6. النشر على الويب مجانًا (خطوة بخطوة)

### الخيار الموصى به: Neon (قاعدة بيانات) + Render (Backend) + Vercel (Frontend)

#### أ) قاعدة البيانات — Neon.tech (PostgreSQL مجاني دائم)
1. أنشئ حسابًا مجانيًا على https://neon.tech
2. أنشئ مشروعًا جديدًا واحصل على `DATABASE_URL` (يبدأ بـ `postgresql://...`)
3. في `backend/prisma/schema.prisma` غيّر:
   ```prisma
   datasource db {
     provider = "postgresql"   // بدل "sqlite"
     url      = env("DATABASE_URL")
   }
   ```
4. شغّل محليًا: `npx prisma migrate dev --name init_postgres` لتطبيق المخطط على القاعدة الجديدة، ثم `npm run seed`.

#### ب) الخادم الخلفي — Render.com (Free Web Service)
1. ادفع مجلد `backend/` إلى مستودع GitHub.
2. في Render: New → Web Service → اربط المستودع.
3. Build Command: `npm install && npx prisma generate && npm run build`
4. Start Command: `npm run start`
5. أضف متغيرات البيئة (Environment): `DATABASE_URL` (من Neon)، `JWT_SECRET` (قيمة عشوائية طويلة)، `CORS_ORIGIN` (رابط الـ frontend بعد نشره).
6. بعد أول نشر، شغّل مرة واحدة عبر "Shell" في Render: `npx prisma migrate deploy && npm run seed`.

#### ج) الواجهة الأمامية — Vercel (Free)
1. ادفع مجلد `frontend/` إلى نفس المستودع أو مستودع منفصل.
2. في Vercel: Import Project → اختر مجلد `frontend`.
3. أضف متغير بيئة: `VITE_API_URL=https://اسم-تطبيقك.onrender.com/api`
4. انشر — ستحصل على رابط عام فورًا (مثال: `https://aref-plan-tracker.vercel.app`).

بهذا يصبح التطبيق متاحًا على الإنترنت بالكامل مجانًا، بدون أي بطاقة بنكية.

> ملاحظة: الباقة المجانية لـ Render تُدخل الخادم في وضع سكون بعد فترة عدم استخدام، فيستغرق أول طلب بعد ذلك بضع ثوانٍ إضافية لإعادة التشغيل — هذا طبيعي في الباقات المجانية ولا يؤثر على البيانات.

## 8. ما تم تنفيذه فعليًا (متصل بقاعدة بيانات حقيقية، لا Mock)

جميع النقاط التالية تعمل فعليًا وتقرأ/تكتب في قاعدة البيانات مباشرة:

- تسجيل الدخول (JWT) + ربط المستخدم بدوره ومديريته
- اختيار السنة الدراسية إجباريًا، ابتداءً من 2026/2027 (قابل للتوسع من الإعدادات)
- إضافة/تعديل/حذف/نسخ العمليات + Validation كامل بالعربية
- عزل صارم بين المديريات على مستوى الـ API
- زر "تم الإنجاز" مع منطق تلقائي للوضعية والتاريخ
- حساب نسبة الإنجاز ديناميكيًا
- تحديد العمليات المتأخرة ديناميكيًا
- لوحة القيادة الإقليمية (Cards + 3 رسوم بيانية + العمليات المتأخرة/القريبة) — كل الأرقام من قاعدة البيانات
- لوحة القيادة الجهوية + مقارنة المديريات الثمانية + الانتقال إلى تفاصيل كل مديرية
- البحث والتصفية والفرز والـ Pagination في جدول العمليات
- استيراد Excel مع معاينة الأخطاء قبل التأكيد (رقم الصف، الحقل، سبب الخطأ)
- تصدير Excel وCSV حسب الفلاتر الحالية
- التقارير المجمّعة (حسب المديرية/الوضعية/المنسق/المؤشر)
- إدارة المستخدمين (Admin)
- سجل التغييرات (Audit Log) يسجل من قام بماذا ومتى والقيم قبل/بعد

### قابل للتوسع لاحقًا (مصمم البنية لدعمه دون إعادة هيكلة)
- تصدير PDF للتقارير
- المرفقات والتعليقات على العمليات
- الإشعارات التلقائية (اقتراب الموعد النهائي)
- صلاحيات أكثر تفصيلًا داخل نفس الدور
